# 「会議中」の画面

「会議中」の画面（S-03）の作りと、動作の確認です。設計の根拠は、基本設計書の画面設計書「S-03 会議中の領域」「S-03 会議中の項目と操作」「複数の画面で使う項目」、機能設計書 F-06・F-14、ADR-15 にあります。

## 画面の作り

| 領域 | 中身 | 部品 |
|---|---|---|
| 状況の領域 | タイトル、経過時間（1 秒ごと）、取り込み中の音声の出どころ、字幕の状況、会議を終了するボタン | `screens/live/LiveMeetingView.tsx`、字幕の状況は `components/subtitles/SubtitleStatusFact.tsx` |
| 字幕の領域 | 話された順の字幕。最新まで自動で進む。過去へ戻っている間は進まず、「最新の字幕へ戻る」を出す | `components/subtitles/LiveSubtitleView.tsx` |
| 案内の領域 | 英語の発言だけが対象であること、ブラウザーを開いたままにすること（F-14） | `screens/live/LiveGuidance.tsx` |

質問の領域は、この画面にまだ無い（後の作業で足す）。取り込み停止の選択は、お知らせ帯に出る（下の「取り込み停止の選択」）。「会議中」のヘッダと画面に、ほかの画面へ移るリンクは置かない。

## 会議の情報の受け取り方

「会議中」は、会議の開始の応答（`POST /api/meetings`）を、画面の移動の状態（`location.state.meeting`）から受け取ります。「会議の準備」の画面は、会議を開始できたら、次のように移ります（`meetings/liveMeeting.ts`）。

```ts
navigate(screenPaths.meetingLive(meeting.meeting_id), { replace: true, state: { meeting } });
```

URL を直接開いた・再読み込みしたなど、状態を読み取れないときは、「会議の記録」へ移ります（履歴は置き換え）。その会議の音声を送る接続はすでに切れていて、アプリサーバーが会議を中断にしているためです（画面設計書の画面遷移）。

再読み込みでは、ブラウザーの履歴の状態が残ります。ページを読み込んだ時点で、再読み込みまたは戻る・進むによる読み込みであり、履歴の状態に会議が残っていれば、その会議番号を控えて、「会議中」では使いません（`staleMeetingIdFrom`）。再読み込みのあとに、会議の開始から移ってきた状態は、別の会議番号のため、通常どおり表示します。

タイトルは会議の内容のため、URL に載せず、ブラウザーの保存領域にも書きません。

## 字幕の状況と警告

- 字幕の状況（`components/subtitles/SubtitleStatusFact.tsx`）は、状況の領域の項目として出す。5 つの状況（開始準備中・正常・遅れ・無音の待機・取り込み停止）を、表示名の文字・形の違うアイコン・色の 3 つで示す。色だけに頼らない（受入条件）。補足の文（例: 「字幕の遅れが目標を超えています」）を添える。文字と背景の明るさの差は 7 対 1 以上
- 項目は `aria-live="polite"`・`aria-atomic="true"` の領域に置く。状況が変わると、読み上げソフトが、いまの読み上げを妨げずに、項目名・状況・補足をまとめて伝える。領域は最初から文書に置き、中身だけが変わる。アイコンは `aria-hidden`
- 状況は `meetings/useLiveStatus.ts` が持つ。開いた時点で `GET /api/meetings/{会議番号}/live-status` を読み（応答が届くまでは開始準備中）、通知 `subtitle_status.changed` で置き換える。通知を受けたあとに届いた応答の状況は捨てる（古い値のため）。つなぎ直したときは、サーバーが最初に送る現在の状況の通知で直る。読み込みに失敗しても、エラーは出さない（状況は補助の表示で、字幕の表示と終了の操作を妨げない）
- 遅れの間だけ、お知らせ帯に警告「字幕が目標より遅れています。…」を出す（`useWarning`）。正常などへ戻ると消える
- 会議が 2 時間を超えたことの警告は、経過時間（会議の開始日時からの差。1 秒ごとに進む）が、`live-status` の `meeting_length_warning_seconds`（調整値。既定 7,200 秒）を超えたときに出す。ちょうど 7,200 秒では出さない。利用者は閉じられず、画面を離れる（会議を終了する）まで残る。会議は止めず、字幕の表示と終了の操作は、警告が出ていても動く。画面を開き直したときは、経過時間から判定して、すぐ出す。調整値を読めるまでは出さない。読めなかった（`live-status` が失敗した）ときは、既定の 7,200 秒で判定する（`meetings/useLiveStatus.ts` の `DEFAULT_LENGTH_WARNING_SECONDS`）。文面の経過時間は、調整値から組み立てる（`meetings/guidanceTexts.ts` の `meetingLengthWarning`）

## 取り込み停止の選択

会議中に音声の共有（またはマイクの音声）が止まると、アプリサーバーが字幕の状況を「取り込み停止」にして通知します（[会議の管理](meetings.md)の「字幕の状況」）。画面は、`meetings/useCaptureStoppedChoice.ts` が、状況が取り込み停止の間、お知らせ帯に「選択を求めるお知らせ」（`kind: 'choice'`、コード `AUDIO_CAPTURE_STOPPED`）を出します。それまでの字幕は、そのまま残ります。

| 選択 | 動き |
|---|---|
| 取り込みをやり直す | `MeetingCaptureProvider` の `restart()` を呼ぶ。開始時に選んだ音声の出どころで、ブラウザーの共有と許可の確認が出る。同じ接続のまま音声が続き、アプリサーバーが再開を通知すると、状況が戻る。会議は終了しない |
| 会議を終了する | 終了の確認を出さずに、`endNow`（取り込みを止める → 終了の API → 接続を閉じる）を呼び、「会議の記録」へ移る。この選択が確認を兼ねる。状況の領域の「会議を終了する」ボタンは、これまでどおり確認を出す |

- どちらかを選ぶと、お知らせは消える。お知らせが出た時点で、フォーカスを 1 つ目のボタン（取り込みをやり直す）へ移す（`NoticeBand`。選択を求めるお知らせだけ）。キーボードだけで選べる
- やり直しに失敗したときは、取り込み停止にとどまる。失敗の理由（`AUDIO_PERMISSION_DENIED` など）を添えて、選択のお知らせを出し直し（もう一度選べる）、状況の領域のすぐ下に、取り込みの手順（`screens/live/CaptureRestartGuidance.tsx`。文言は `meetings/guidanceTexts.ts` の `RESTART_GUIDANCE_STEPS`）を出す。やり直しに成功する、または状況が戻ると、手順は消える
- 終了の処理の間（`ending`。選択のお知らせからでも、状況の領域の「会議を終了する」の確認からでも）は、選択のお知らせを消す。終了の依頼は 1 回だけ（`endNow` は、動いている間に呼ばれても何もしない）。失敗して戻ると、取り込み停止のままなので、選択のお知らせが出し直される（終了の失敗のエラーも出る）
- 状況が取り込み停止から戻る、または画面を離れると、お知らせを片づける
- お知らせは、取り込み停止になった時点で 1 回だけ出す。時点は、状況の値の変化と、取り込み停止の通知を受けた回数（`useLiveStatus` の `captureStopCount`）の増加の両方で決める。再開と停止の通知が続けて届き、1 回の描画にまとまると、状況の値は取り込み停止のまま変わらないが、回数は増えるため、選択が出し直される。描画のたびには出し直さない
- 選択を選んだ直後に、フォーカスを状況の領域の見出し（会議のタイトル。`tabindex=-1`）へ移す。選んだボタンはお知らせとともに消えるため、移さないと、フォーカスが文書の先頭へ落ちる。やり直しに失敗して選択が出し直されたときは、1 つ目のボタンへ戻る
- 状況が戻る、または新しく止まる（回数が増える）と、やり直しの失敗の記録（手順の案内）を忘れる

## 字幕の処理のエラー

会議中に字幕の処理が失敗すると、アプリサーバーが `error.occurred` を通知します。画面は、`meetings/useSubtitleErrorNotices.ts` が、お知らせ帯のエラー（`kind: 'error'`）として出します。会議と字幕の表示は続きます。

- 表示するのは、この会議の通知のうち、`SUBTITLE_ERROR_CODES` のコード（`SUBTITLE_TRANSCRIPTION_FAILED`・`SUBTITLE_SAVE_FAILED`）だけです。別の会議の通知は使いません。会議の終了の保存の失敗は、終了の応答のエラーとして、画面が別に出すため、ここでは出しません。同じ出来事のお知らせを重ねないためです。通訳ワーカーの停止（`SYSTEM_INTERPRETER_UNAVAILABLE`）と、要約・質問の作成の失敗も、この部品では出しません。
- 文言は、エラーコードから `errorMessages.ts` の一覧で引きます。サーバーが通知に書いた文面は、読み替えの時点で捨てます。
- 字幕の保存の失敗（`SUBTITLE_SAVE_FAILED`）では、失敗した字幕が一覧に載りません。アプリサーバーが、保存が確定した字幕だけを通知するためです。画面に出ている字幕は、すべて記録に残っています。お知らせには、会議は続けられること、続けて出るときは、ディスクの空きを確かめることを書きます。保存の失敗は、字幕が上限（2,000 文字）を超える場合や、書き込みの待ち時間切れでも起きるため、ディスクの空きを原因として決めつけません。
- お知らせの識別子はコードごとに 1 つです。同じコードの通知が続いても、お知らせは増えず、内容が置き換わります。アプリサーバーも、同じ失敗の通知を、調整値 `error_notice_interval_seconds`（60 秒）につき 1 件へ絞って送ります。
- お知らせは、利用者が「エラーを閉じる」を押すと消えます。同じ操作が成功した場合も消えます。この会議の字幕の通知（`subtitle.created`）が届くと、文字起こしと保存が成功したので、2 つのお知らせをどちらも消します。失敗が続く間は字幕が届かないため、お知らせは残ります。消えたあとで同じ失敗の通知が届けば、もう一度出ます。別の会議の字幕では消しません。
- 画面を離れる（会議を終了して「会議の記録」へ移る、など）と、お知らせを片づけます。お知らせの文面は、進行中の会議の続け方（「会議はそのまま続けられます」）を伝えるもので、会議を終えたあとの画面に残ると読み違えるためです。保存できなかった字幕は、「会議の記録」の字幕の一覧に載りません（記録に残っているものだけが載ります）。

## 字幕

- 字幕の行（`components/subtitles/SubtitleRow.tsx`）は、「会議の記録」でも使い回す。話された時刻（秒まで、PC のタイムゾーン）・英語の原文・日本語訳を並べる。日本語訳が空のときは、「日本語訳を作れませんでした。」を出す
- 字幕は、React の文字の出力だけで表示する。HTML や Markdown として解釈しない（ADR-15）
- 一覧は `subtitles/mergeSubtitles.ts` で、順番（`sequence`）が同じ字幕を 1 回だけ持つ。開いた時点の読み込み、通知 `subtitle.created`、再接続のあとの読み直しが重なっても、表示は重ならない
- 追いかけているかは、スクロール位置で判定する（最下部から 24px 以内）。過去へ戻っている間に字幕が増えても、位置は動かない
- 字幕の領域は Tab で止まれる。矢印キーなどで過去へ戻れる。「最新の字幕へ戻る」を押すと、フォーカスが字幕の領域へ移る
- 1 回の会議で最大 約 1,500 件。単純な描画にしている（行は `memo`）。遅いときは仮想化を検討する。1,500 件での描画の速さは測っていない

### 字幕の状況と会議の長さの警告の確認

出荷するコンテナを作り直し（`docker compose build` → `up -d`）、`playwright-cli`（headless Chromium 1254、画面幅 1280・640）で確かめました。会議は、確認用のスクリプトが `POST /api/meetings` で始め、`/ws/audio/{会議番号}` へ英語の音声（約 11 秒の演説。繰り返す）か無音を実時間で送りました。画面は、ブラウザーの履歴の状態を `pushState` で置いて、「会議中」を開きました（上の「会議の情報の受け取り方」）。本物のモデルで動かしています。スクリーンショットは `ai_generated/screenshots/` の `pbi-4-2_*.png` です。

調整値は、確かめる時間を短くするため、上書きファイル（リポジトリの外。`docker compose -f docker-compose.yml -f <上書きファイル> up -d`）で `MMD_TUNING_SILENCE_WAIT_SECONDS=3`・`MMD_TUNING_SUBTITLE_DELAY_TARGET_SECONDS=1`・`MMD_TUNING_MEETING_LENGTH_WARNING_SECONDS=60` にしました。確認のあとは、`docker compose up -d` だけで戻します。

### 取り込み停止の選択の確認

### 字幕の処理のエラーの確認
