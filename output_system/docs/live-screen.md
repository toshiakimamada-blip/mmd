# 「会議中」の画面

「会議中」の画面（S-03）の作りと、動作の確認です。設計の根拠は、基本設計書の画面設計書「S-03 会議中の領域」「S-03 会議中の項目と操作」「複数の画面で使う項目」、機能設計書 F-06・F-14、ADR-15 にあります。

## 画面の作り

| 領域 | 中身 | 部品 |
|---|---|---|
| 状況の領域 | タイトル、経過時間（1 秒ごと）、取り込み中の音声の出どころ、会議を終了するボタン | `screens/live/LiveMeetingView.tsx` |
| 字幕の領域 | 話された順の字幕。最新まで自動で進む。過去へ戻っている間は進まず、「最新の字幕へ戻る」を出す | `components/subtitles/LiveSubtitleView.tsx` |
| 案内の領域 | 英語の発言だけが対象であること、ブラウザーを開いたままにすること（F-14） | `screens/live/LiveGuidance.tsx` |

質問の領域と、字幕の状況・遅れの警告・取り込み停止の選択は、この画面にまだ無い（後の作業で足す）。「会議中」のヘッダと画面に、ほかの画面へ移るリンクは置かない。

## 会議の情報の受け取り方

「会議中」は、会議の開始の応答（`POST /api/meetings`）を、画面の移動の状態（`location.state.meeting`）から受け取ります。「会議の準備」の画面は、会議を開始できたら、次のように移ります（`meetings/liveMeeting.ts`）。

```ts
navigate(screenPaths.meetingLive(meeting.meeting_id), { replace: true, state: { meeting } });
```

URL を直接開いた・再読み込みしたなど、状態を読み取れないときは、「会議の記録」へ移ります（履歴は置き換え）。その会議の音声を送る接続はすでに切れていて、アプリサーバーが会議を中断にしているためです（画面設計書の画面遷移）。タイトルは会議の内容のため、URL に載せず、ブラウザーの保存領域にも書きません。

## 字幕

- 字幕の行（`components/subtitles/SubtitleRow.tsx`）は、「会議の記録」でも使い回す。話された時刻（秒まで、PC のタイムゾーン）・英語の原文・日本語訳を並べる。日本語訳が空のときは、「日本語訳を作れませんでした。」を出す
- 字幕は、React の文字の出力だけで表示する。HTML や Markdown として解釈しない（ADR-15）
- 一覧は `subtitles/mergeSubtitles.ts` で、順番（`sequence`）が同じ字幕を 1 回だけ持つ。開いた時点の読み込み、通知 `subtitle.created`、再接続のあとの読み直しが重なっても、表示は重ならない
- 追いかけているかは、スクロール位置で判定する（最下部から 24px 以内）。過去へ戻っている間に字幕が増えても、位置は動かない
- 字幕の領域は Tab で止まれる。矢印キーなどで過去へ戻れる。「最新の字幕へ戻る」を押すと、フォーカスが字幕の領域へ移る
- 1 回の会議で最大 約 1,500 件。単純な描画にしている（行は `memo`）。遅いときは仮想化を検討する。1,500 件での描画の速さは測っていない

## 動作の確認（出荷するコンテナ）

`docker compose build` で作り直したイメージのコンテナ（開発用コンテナからコンテナ名で接続）を、`playwright-cli`（Chromium 1248、画面幅 1280・390）で開いて確かめました。会議は、`POST /api/meetings` で始め、`/ws/audio/{会議番号}` へ、英語の演説（faster-whisper の `tests/data/jfk.flac`）を実際の速さで送りました（本物のモデル）。「会議の準備」の画面がまだ無いため、ブラウザーの履歴へ `{ meeting }` の状態を書いて「会議中」を開きました（アプリにテスト専用の入口は無い）。

| 確かめたこと | 結果 | スクリーンショット（`ai_generated/screenshots/`） |
|---|---|---|
| タイトル（`<b>週次</b> の定例 & <i>planning</i>`）が文字のまま出る。経過時間が進む。音声の出どころの表示名。字幕が原文・日本語訳・時刻つきで並ぶ | 合格 | `task-67_meeting-live-subtitles.png` |
| 字幕が増えると、最下部（最新）まで進む（10 行で `scrollTop` = 最大値） | 合格 | — |
| 最上部へ戻ると、「最新の字幕へ戻る」が出る。字幕が 7 行から 10 行へ増えても、位置は 0 のまま、ボタンも残る | 合格 | `task-67_meeting-live-jump-button.png`、`task-67_meeting-live-reading-older.png` |
| 「最新の字幕へ戻る」で最下部へ進み、ボタンが消え、フォーカスが字幕の領域へ移る | 合格 | — |
| 「会議を終了する」で確認が出る。Esc で取りやめるとフォーカスが元のボタンへ戻る。Enter → Tab → Enter（キーボードだけ）で終了し、「会議の記録」へ移る。字幕 15 件が保存されている | 合格 | `task-66_meeting-live-end-confirm.png`、`task-66_meeting-record-after-end.png` |
| コンテナを止めると、お知らせ帯に「アプリとつながっていません」が出て、画面の字幕は残る。コンテナを起動すると、帯が消え、字幕を取得し直した（`/subtitles` の取得が 2 回から 3 回へ） | 合格 | `task-65_meeting-live-offline-notice.png` |
| 画面幅 390px で、状況・字幕が折り返して読める | 合格 | `task-66_meeting-live-narrow.png` |

確かめていないことは次のとおりです。

- HTML の記号を含む字幕を、実ブラウザーで表示した結果。本物のモデルの字幕に、記号を含ませられないため。Vitest（jsdom）で、通知で届いた字幕と取得した字幕の両方を確かめた。タイトルは、実ブラウザーで確かめた
- 切れている間に出た字幕を、つなぎ直しのあとの読み直しで埋める動き。実ブラウザーでは、読み直しの取得が起きたことまでを確かめた。抜けが埋まる中身は Vitest で確かめた（アプリを止めると、会議も中断になるため）
- 利用者の PC（Windows の Edge）、実際の PC の音声、画面を読み上げるソフト、2 時間・約 1,500 件の字幕での描画
