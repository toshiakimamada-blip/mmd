# 「会議の一覧」の画面

「会議の一覧」の画面（S-01）の作りと、動作の確認です。設計の根拠は、基本設計書の画面設計書「S-01 会議の一覧の領域」「S-01 会議の一覧の項目と操作」「状態別の表示と操作」、機能設計書 F-09・F-10・F-14・F-15、ADR-15 にあります。

暫定版（2026-11-16 まで）では、記録の削除を置きません。「削除」のボタンは、すべての行で押せない見た目のまま残します（動作は、記録の削除を作る作業で足します）。

## 画面の作り

上から順に、「新しい会議を始める」 → 使い方の流れ → 会議の行の順に並べます。

| 領域 | 中身 | 部品 |
|---|---|---|
| 「新しい会議を始める」 | 「会議の準備」（S-02）へ移るリンク | `screens/MeetingListScreen.tsx` |
| 使い方の流れ | 3 つの手順。会議の件数に関わらず、常に表示する | `screens/list/UsageFlow.tsx`、文言は `meetings/guidanceTexts.ts` |
| 会議の行 | タイトル、開始日時（分まで）、会議の長さ（秒まで。通訳中は出さない）、状態（区分の表示名）、「開く」、「削除」 | `screens/list/MeetingRow.tsx` |
| 会議が 0 件のとき | 行の代わりに、記録がまだ無いことと、新しい会議の始め方を案内する | `screens/list/MeetingListBody.tsx` |

- 並び順は、アプリサーバーが返した順（開始日時の新しい順）のままです。画面では並べ替えません
- 開始日時は、保存した UTC を、PC に設定されたタイムゾーンへ変換して表示します（`records/formatDateTime.ts`）
- 会議の長さは、開始日時と終了日時から求めます。通訳中の会議と、終了日時が無い会議では出しません
- 通訳中の行だけ、左に黄色の棒を付けます。状態は文字でも出すため、色だけには頼りません
- 「開く」は、どの状態でも押せます。画面の移動のため、リンクにしています（移る先は「会議の記録」）
- 「削除」は、状態が中断・完了・要約失敗で、作成ジョブが無いときに、押せる条件を満たします（`records/recordView.ts` の `isDeletable`）。ただし、削除の動作を渡さない間は、条件を満たす行でも押せません
- 「開く」と「削除」は、タイトルを説明として結び付けます。読み上げソフトが、どの会議の操作かを伝えられます
- タイトルは会議の内容です。文字として表示し、HTML としては解釈しません（ADR-15）

## 読み込みと通知での更新

`GET /api/meetings` で、すべての会議を 1 回で読みます（`records/useMeetingList.ts`）。ブラウザーの HTTP キャッシュは使いません。

| きっかけ | 動き |
|---|---|
| 画面を開いたとき、画面を再読み込みしたとき | 読み込む。結果が届くまでは「会議の一覧を読み込んでいます。」だけを出し、記録が無いという案内は出さない |
| 会議の状態の通知（`meeting.state_changed`） | 読み直す。会議の開始・終了・中断・要約の結果で、行と状態が変わる |
| 作成ジョブの状況の通知（`job.status_changed`） | 読み直す。質問の作成は会議の状態を変えないため、作成ジョブの有無（削除を押せるかの判定）は、この通知でしか変わらない |
| 進み具合（`job.progress_changed`）と字幕（`subtitle.created`）の通知 | 読み直さない（一覧は表示しない） |
| 通知の接続がつながったとき（つなぎ直しを含む） | 読み直す。切れていた間の通知の分を埋める |
| 読み込みに失敗したとき | お知らせ帯にエラーを出す。すでに表示している一覧は残す。最初の読み込みの失敗だけ、一覧の領域に「もう一度読み込む」を出す。次に読み込めるとエラーは消える |

読み込みを重ねたときは、最後に送った読み込みの結果だけを使います。画面から離れたあとに届いた応答では、何もしません。

## ディスクの空きの警告

記録を置く場所の空きが少ないとき、「会議の一覧」と「会議の準備」を開いた時点で、お知らせ帯に警告を出します（F-15）。警告のみです。保存は止めず、保存する件数にも上限を置きません。

| 部分 | 中身 | 部品 |
|---|---|---|
| 空きの判定 | 記録データベースの置き場（名前付きボリュームのマウント先）があるディスクの空きを、一般の利用者のプロセスが使える量で読む。調整値（`tuning.toml` の `disk_free_warning_gigabytes`。既定は 1GB。1GB は 1024 の 3 乗バイト）を下回ると警告が要る。ちょうど同じ量は、下回っていない。結果は覚えず、聞かれるたびに読み直す | `backend/src/meeting_interpreter/records/disk_space.py` |
| 経路 | `GET /api/system/alerts`。警告の種類の一覧だけを返す（`{"alerts": ["disk_space_low"]}`、無いときは `{"alerts": []}`）。置き場のパスと空きの量は返さない。ディスクへの問い合わせは別のスレッドで動かし、字幕の通知や画面との通信を止めない | `backend/src/meeting_interpreter/api/system.py` |
| 画面の部品 | 画面を開いた時点で 1 回だけ問い合わせ、下回っていればお知らせ帯に警告を出す。画面を離れると消える。空きが戻れば、画面を開き直すと出ない。「会議の一覧」と「会議の準備」が同じ部品を使い、画面を移っても警告は 1 件のまま | `frontend/src/system/useDiskSpaceWarning.ts`、`api/systemApi.ts` |
| 文面 | 何が起きたか（記録を保存する場所の空きが少ない、空きがなくなると保存できない）と、次に行う操作（不要な会議の記録を削除する、PC のほかのファイルを削除する）を書く | `meetings/guidanceTexts.ts` の `DISK_SPACE_LOW_WARNING` |

- 空きを読めなかったときは、「空きは十分」とは答えません。アプリサーバーの想定外の例外として、システムエラー（`SYSTEM_UNEXPECTED_ERROR`）で返り、ログに残ります。画面は、補助の情報のため、警告を出さずに主な内容を表示します。アプリサーバーが返したエラー以外の例外は、握りつぶさず上へ出します
- 警告の問い合わせは、一覧や準備の表示を待たせません（応答が届いてから警告を出す）
- 空きの警告の値は、環境変数 `MMD_TUNING_DISK_FREE_WARNING_GIGABYTES` でも上書きできます（0.1 以上 10000 以下）

## 動作の確認（出荷するコンテナ）

2026-11-17 に、`docker compose build` で作り直したイメージのコンテナ（準備状況が `ready`、本物のモデル）を、開発用コンテナから `playwright-cli`（Chrome、画面幅 1280）でコンテナ名の URL で開いて確かめました。ブラウザーの設定ファイルは、リポジトリの外（`/tmp`）に置きました。画面の PC のタイムゾーンは UTC です。アプリにテスト専用の入口はありません。

| 確かめたこと | 結果 | スクリーンショット（`ai_generated/screenshots/`） |
|---|---|---|
| 46 件の会議（中断・要約作成中・完了）が、開始日時の新しい順に出る。タイトル・開始日時・会議の長さ・状態（中断・要約作成中・完了）・「開く」・押せない「削除」がそろう。タイトル `<b>週次</b> & 定例` は、タグを解釈せず、文字のまま出る（行の中に子の要素が無いことも確認した） | 合格 | `task-121_meeting-list.png`、`task-121_meeting-list-html-titles.png` |
| キーボードだけ: Tab で「新しい会議を始める」 → 「開く」 → 次の行の「開く」の順に進む（押せない「削除」は飛ばされる）。Enter で「会議の記録」へ移る。「新しい会議を始める」を Enter で押すと「会議の準備」へ移る | 合格 | — |
| 別のブラウザーで会議を始めると、開いたままの一覧が、再読み込みなしで 47 行になり、先頭の行が「通訳中」で、会議の長さが出ない。タイトル `<i>` は文字のまま | 合格 | `task-121_meeting-list-interpreting-live-update.png` |
| その会議を終了すると、開いたままの一覧の先頭の行が、再読み込みなしで「完了」（会議の長さ 0:00:30）になる | 合格 | — |
| 記録の置き場を空にしたコンテナ（一時。確認のあとに削除）で開くと、記録がまだ無いことと、新しい会議の始め方の案内が出る。使い方の流れも出ている | 合格 | `task-121_meeting-list-empty.png` |
| 空きが十分（既定の 1GB。空きは約 909GB）: `GET /api/system/alerts` が `{"alerts":[]}`。「会議の一覧」と「会議の準備」に警告が出ない | 合格 | `task-122_prepare-enough-space.png` |
| 空きが少ない状態: 調整値の環境変数を 10000（GB）にして作り直したコンテナで、`GET /api/system/alerts` が `{"alerts":["disk_space_low"]}`。「会議の一覧」と「会議の準備」のお知らせ帯に、警告の種類（エラーではない）で文面が出る。「会議の一覧」から「会議の準備」へ移っても警告は 1 件。「会議の記録」では出ない。AI モデルは「準備完了」のままで、警告のみ | 合格 | `task-122_list-low-disk-warning.png`、`task-122_prepare-low-disk-warning.png` |
| 調整値を元に戻して作り直したコンテナで、警告が出ない | 合格 | — |

確かめていないことは次のとおりです。

- 本物のディスクを埋めた状態の警告。ディスクを埋めると、ほかの作業に障害が出るため、調整値を大きくして、空きが下回った状態を作りました。空きの判定そのものは、空きの量を差し替えた単体テストで、1GB の前後とちょうど 1GB を確かめました
- PC のタイムゾーンが UTC 以外のときの、開始日時の変換。Vitest で、固定したタイムゾーンを渡して確かめました
- 一覧を読み込めなかったときの表示と「もう一度読み込む」、通知の接続のつなぎ直しでの読み直し。Vitest で確かめました（実機では失敗を起こしていません）
- 「削除」を押せる状態。削除の動作を渡していないため、実機のすべての行で押せません。押せる条件の判定は、Vitest で確かめました
