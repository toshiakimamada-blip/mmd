# 「会議の記録」の画面

「会議の記録」の画面（S-04）の作りと、動作の確認です。設計の根拠は、基本設計書の画面設計書「S-04 会議の記録の領域」「S-04 会議の記録の項目と操作」「状態別の表示と操作」「複数の画面で使う項目」、機能設計書 F-10・F-15、ADR-15 にあります。

質問を作るボタンと、Markdown のファイルの取り出しは、まだ置きません。質問は、まとまりがあれば表示し、なければ「質問はまだありません。」と表示するところまでです。記録の削除は [meetings.md](meetings.md) の「記録の削除」、コピーは下の[記録のコピー](#記録のコピー)にあります。

## 画面の作り

| 領域 | 中身 | 部品 |
|---|---|---|
| 見出しの領域 | タイトル、開始日時、会議の長さ（通訳中は出さない）、状態、「一覧へ戻る」 | `screens/record/RecordHeader.tsx` |
| 要約の領域 | 状態に応じた内容（会議中・中断・内容なし・作成中・要約・失敗）と、「要約を作る」「要約を作り直す」「要約をコピーする」のボタン | `screens/record/SummaryRegion.tsx`、`SummaryContent.tsx`、`SummaryProgress.tsx` |
| 質問の領域 | 質問の作成状況（待機中・作成中）、質問のまとまり（新しい順。作成日時・作成した時点・質問 5 問を英語と日本語で並べる。まとまりごとに「質問をコピーする」） | `screens/record/QuestionRegion.tsx`、`components/questions/QuestionSetList.tsx` |
| 字幕の領域 | 話された順の字幕（「会議中」と同じ `SubtitleRow`）と、「字幕をコピーする」 | `screens/record/SubtitleRegion.tsx` |

要約の 4 項目は、保存した文字列を 1 行ずつ箇条書きにして、文字として表示します（`records/summaryLines.ts`）。HTML や Markdown としては解釈しません。

## 状態別の表示と操作

会議の状態・字幕の件数・要約の有無・作成ジョブから、要約の領域の内容とボタンを決める表は、`records/recordView.ts` の 1 か所にあります（純粋な関数）。表のすべての行を `test/records/recordView.test.ts` が確かめます。質問を作るボタンと削除の可否も同じ関数が答えますが、暫定版は画面に置きません。ボタンを足すときに、出し分けを作り直さないためです。

## 記録の読み込みと通知での更新

`GET /api/meetings/{会議番号}` で、会議・字幕・要約・質問のまとまり・作成ジョブを 1 回で読みます（`records/useMeetingRecord.ts`）。

| きっかけ | 動き |
|---|---|
| 会議が無い | 「会議の一覧」へ移り（履歴は置き換え）、お知らせ帯に記録が見つからないことを出す |
| 読み込みの失敗 | お知らせ帯にエラーを出す。次に読み込めると消す |
| `meeting.state_changed`・`job.status_changed` | 記録を読み直す |
| `job.progress_changed` | 作成ジョブの処理したブロックの数だけを差し替える（ブロックごとに届くため、読み直さない） |
| 通知の接続がつながった（つなぎ直しを含む） | 記録を読み直す |
| ほかの会議の通知 | 読み捨てる |

要約の失敗は、会議に保存したエラーコードから表示します。画面を開き直しても同じ表示になります。

## 記録のコピー

要約・質問のまとまりごと・字幕を、ボタンでクリップボードへ入れます（F-12）。文面は、読み込み済みの会議記録から画面が組み立てます（ADR-15）。アプリサーバーへ要求を送りません。

| 部品 | 役割 |
|---|---|
| `records/recordText.ts` | 文面を組み立てる純粋な関数（`buildSummaryText`・`buildQuestionSetText`・`buildSubtitlesText`）。プレーンテキスト。会議の内容の記号は変換しない |
| `records/useClipboardCopy.ts` | `navigator.clipboard.writeText` で書き込み、結果を伝える。成功は `copied`（2 秒）、失敗はお知らせ帯と `manualText` |
| `components/records/CopyButton.tsx` | ボタン・「コピーしました」（`aria-live="polite"`）・失敗したときの文面の欄。要約・質問・字幕で使い回す |

### 文面の形

要約:

```
【全体の概要】
予算案を承認しました。

【話題ごとの要点】
・予算案: 承認された
・作業の分担: 来週決める

【決定事項】
・予算案を承認する

【宿題】
・該当なし
```

質問のまとまり 1 つ:

```
1. What is the budget plan?
   予算案は何ですか。

2. Who owns the task?
   誰が担当ですか。
```

字幕（時刻は PC のタイムゾーン）:

```
10:00:01 English line 1
日本語訳 1

10:00:02 English line 2
（訳なし）
```

- 要約: 4 項目の見出しを【】で囲む。全体の概要は文のまま、ほかの 3 つは 1 行 1 項目の「・」。内容が無い項目は「該当なし」。作成日時は含めない。
- 質問のまとまり: 「番号. 英語の質問」の次の行に、字下げした日本語の質問。まとまりの見出しと作成日時は含めない。
- 字幕: 「時刻 英語の原文」の次の行に日本語訳。日本語訳が無い字幕は「（訳なし）」。時刻は、字幕の行と同じ整形（`formatClockTime`。時:分:秒、PC のタイムゾーン）。
- 項目と項目の間は空行 1 行。末尾に改行を付けません。

Markdown の取り出し（PBI 6.4）は、`recordText.ts` の `SUMMARY_TITLES`・`NO_TRANSLATION_TEXT` と、`splitSummaryLines`・`formatDateTimeToMinute`・`formatClockTime` を使い回します。会議の内容の記号を、Markdown と HTML の記法として働かない形へ変換する処理は、取り出しの側に足します（コピーは、変換しない）。

### ボタンの出し分け

| ボタン | 置き場所 | 押せる条件 |
|---|---|---|
| 要約をコピーする | 要約の領域。要約を作るボタンの隣 | 要約がある（作り直しの途中や失敗のあとに表示している前の要約を含む） |
| 質問をコピーする | 質問のまとまりごと、質問の下 | 質問が 1 問以上ある |
| 字幕をコピーする | 字幕の領域の先頭 | 字幕が 1 件以上ある |

押せないときも、ボタンは押せない見た目で残します。「会議中」の画面の質問のコピーは、質問の領域がまだ無いため置いていません。質問を作る作業（PBI 5.5）で、`QuestionSetList` に `copyable` を渡すと、同じボタンを置けます。

### 結果の伝え方

| 結果 | 表示 |
|---|---|
| 成功 | 押したボタンの右に「✓ コピーしました」を 2 秒だけ出す。続けて押すと数え直す。お知らせ帯の失敗のお知らせは消す |
| ブラウザーが書き込みを断った（または `navigator.clipboard` が無い） | お知らせ帯にエラー `RECORD_COPY_FAILED`（コピーできなかったことと、欄の文面を選んで Ctrl+C を押す方法）。ボタンの下に、文面を全部選んだ読み取り専用の欄を出し、フォーカスを移す。欄の「閉じる」で閉じると、フォーカスはコピーのボタンへ戻る |

- コピーできるのは、プレーンテキストだけです（`writeText`。HTML の形では書きません）。
- 会議の内容を、ログにもコンソールにも出しません。例外の文面は、画面にも出しません。
- `navigator.clipboard` は、安全な接続（https と `localhost`）のページにだけあります。アプリを `localhost` で開く使い方では使えます。コンテナ名などで開くと、`navigator.clipboard` が無く、上の失敗の表示になります。

## 動作の確認（出荷するコンテナ）

`docker compose build` で作り直したイメージのコンテナ（開発用コンテナからコンテナ名で接続）を、`playwright-cli`（Chrome、画面幅 1280）で開いて確かめました。会議は、`POST /api/meetings` で始め、`/ws/audio/{会議番号}` へ、英語の演説（faster-whisper の `tests/data/jfk.flac`。前に 1 秒、後ろに 2 秒の無音を足した）を実際の速さで送り、`POST /api/meetings/{会議番号}/end` で終えました（本物のモデル。タイトルは `<b>週次</b> & 定例`）。

| 確かめたこと | 結果 | スクリーンショット |
|---|---|---|
| 通訳中の会議を開くと、それまでの字幕が出て、要約の欄に会議中であることが出る | 合格 | `task-108_record-while-interpreting.png` |
| 終了の直後、状態が要約作成中になり、要約の欄に作成状況（待機中と、待機中の添え書き）が出る | 合格 | `task-108_record-summary-starting.png` |
| 要約の作成中は、作成状況（作成中）と、処理したブロックの数が出る | 合格 | `task-108_record-summary-running.png` |
| 完了すると、4 項目・箇条書き・「該当なし」・作成日時・「要約を作り直す」が出る。タイトルの HTML は文字のまま | 合格 | `task-108_record-summary-done.png` |
| 「要約を作り直す」を押すと、作成状況（待機中）と、待機中の添え書き、前の要約が出る | 合格 | `task-108_record-summary-rebuilding.png` |
| 開いたまま（読み直しなし）で作成が終わると、新しい要約（作成日時が進む）に変わり、状態が完了になる | 合格 | `task-108_record-summary-rebuilt-by-notification.png` |

最後の確認は字幕 3 件の会議で、要約の作成に約 2 分でした（この開発環境）。それ以前の確認は、約 80 秒の会議（字幕 17 件）です。

実ブラウザーでは確かめていません（Vitest で確かめました）: 要約の失敗の表示、質問のまとまりの表示（暫定版では質問を作れないため）、画面幅 390、2 時間・約 1,500 件の字幕の描画（Vitest は 1,500 件の表示を確かめます）。

### 記録のコピーの確認

作り直した出荷イメージのコンテナ（コンテナ名で接続）を、`playwright-cli`（Chrome 156、画面幅 1280・390）で開いて確かめました。記録は、すでにある完了の会議（字幕 3 件・要約・質問のまとまり 6 つ。本物のモデルが作ったもの）です。

| 確かめたこと | 結果 | スクリーンショット |
|---|---|---|
| コンテナ名で開くと、`isSecureContext` が false で `navigator.clipboard` が無い。「要約をコピーする」を押すと、お知らせ帯にエラーと `RECORD_COPY_FAILED` が出て、ボタンの下の欄に文面が全選択で出る。フォーカスは欄にある | 合格 | `task-129_record-copy-refused.png` |
| 画面幅 390 でも、欄がはみ出さず折り返される | 合格 | `task-129_record-copy-refused-narrow.png` |
| キーボードだけで、Tab → 「閉じる」→ Enter で欄が閉じ、フォーカスがコピーのボタンへ戻る。Enter でもう一度試せる | 合格 | — |
| 字幕 0 件・要約なしの会議で、2 つのコピーのボタンが押せない見た目で残る | 合格 | `task-129_record-copy-disabled-no-content.png` |
| 「この接続を安全な接続として扱う」起動オプションつきの Chrome（タイムゾーンは Asia/Tokyo）で、「字幕をコピーする」を押すと、`navigator.clipboard.readText()` が返す文面の時刻が、画面の時刻と同じ（保存値 UTC 23:26:15 が 08:26:15）。クリップボードの形式は `text/plain` だけ | 合格 | `task-129_record-copy-subtitles-copied.png` |
| 質問のまとまり 1 のボタンで、そのまとまり 5 問の文面だけが入る（API の値から組み立てた文面と一致）。「コピーしました」は、そのまとまりのボタンの隣にだけ出る | 合格 | `task-129_record-copy-question-set-copied.png` |
| 要約を、キーボードの Enter でコピーできる。文面は 4 項目の見出しと内容。「コピーしました」は 2 秒後に消える | 合格 | `task-129_record-copy-summary-copied.png` |

実ブラウザーでは確かめていません（Vitest で確かめました）: 字幕 1,500 件のコピー、HTML の記号を含む内容のコピー。`localhost` で開く確認は、開発用のコンテナから出荷のコンテナへ `localhost` で届かないため、できません。代わりに、コンテナ名の接続を安全な接続として扱う起動オプション（`--unsafely-treat-insecure-origin-as-secure`）を付けた Chrome で、成功の動作を確かめました。
