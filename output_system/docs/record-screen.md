# 「会議の記録」の画面

「会議の記録」の画面（S-04）の作りと、動作の確認です。設計の根拠は、基本設計書の画面設計書「S-04 会議の記録の領域」「S-04 会議の記録の項目と操作」「状態別の表示と操作」「複数の画面で使う項目」、機能設計書 F-10・F-15、ADR-15 にあります。

質問を作るボタンは、まだ置きません。質問は、まとまりがあれば表示し、なければ「質問はまだありません。」と表示するところまでです。記録の削除は [meetings.md](meetings.md) の「記録の削除」、コピーは下の[記録のコピー](#記録のコピー)、Markdown のファイルの取り出しは下の[記録の取り出し](#記録の取り出し)にあります。

## 画面の作り

| 領域 | 中身 | 部品 |
|---|---|---|
| 見出しの領域 | タイトル、開始日時、会議の長さ（通訳中は出さない）、状態、「一覧へ戻る」「取り出す」「記録を削除する」 | `screens/record/RecordHeader.tsx` |
| 要約の領域 | 状態に応じた内容（会議中・中断・内容なし・作成中・要約・失敗）と、「要約を作る」「要約を作り直す」「要約をコピーする」のボタン | `screens/record/SummaryRegion.tsx`、`SummaryContent.tsx`、`SummaryProgress.tsx` |
| 質問の領域 | 質問の作成状況（待機中・作成中）、質問のまとまり（新しい順。作成日時・作成した時点・質問 5 問を英語と日本語で並べる。まとまりごとに「質問をコピーする」） | `screens/record/QuestionRegion.tsx`、`components/questions/QuestionSetList.tsx` |
| 字幕の領域 | 話された順の字幕（「会議中」と同じ `SubtitleRow`）と、「字幕をコピーする」 | `screens/record/SubtitleRegion.tsx` |
| 案内の領域 | 取り出しの案内（画面の最後。常に表示） | `screens/record/ExportGuide.tsx` |

要約の 4 項目は、保存した文字列を 1 行ずつ箇条書きにして、文字として表示します（`records/summaryLines.ts`）。HTML や Markdown としては解釈しません。

## 状態別の表示と操作

会議の状態・字幕の件数・要約の有無・作成ジョブから、要約の領域の内容とボタンを決める表は、`records/recordView.ts` の 1 か所にあります（純粋な関数）。表のすべての行を `test/records/recordView.test.ts` が確かめます。質問を作るボタンと削除の可否も同じ関数が答えますが、暫定版は画面に置きません。ボタンを足すときに、出し分けを作り直さないためです。

## 記録の読み込みと通知での更新

`GET /api/meetings/{会議番号}` で、会議・字幕・要約・質問のまとまり・作成ジョブを 1 回で読みます（`records/useMeetingRecord.ts`）。

| きっかけ | 動き |
|---|---|
| 会議が無い | 「会議の一覧」へ移り（履歴は置き換え）、お知らせ帯に記録が見つからないことを出す |
| 読み込みの失敗 | お知らせ帯にエラーを出す。次に読み込めると消す |
| `meeting.state_changed`・`job.status_changed` | 記録を読み直す |
| `job.progress_changed` | 作成ジョブの処理したブロックの数だけを差し替える（ブロックごとに届くため、読み直さない） |
| 通知の接続がつながった（つなぎ直しを含む） | 記録を読み直す |
| ほかの会議の通知 | 読み捨てる |

要約の失敗は、会議に保存したエラーコードから表示します。画面を開き直しても同じ表示になります。

## 記録のコピー

要約・質問のまとまりごと・字幕を、ボタンでクリップボードへ入れます（F-12）。文面は、読み込み済みの会議記録から画面が組み立てます（ADR-15）。アプリサーバーへ要求を送りません。

| 部品 | 役割 |
|---|---|
| `records/recordText.ts` | 文面を組み立てる純粋な関数（`buildSummaryText`・`buildQuestionSetText`・`buildSubtitlesText`）。プレーンテキスト。会議の内容の記号は変換しない |
| `records/useClipboardCopy.ts` | `navigator.clipboard.writeText` で書き込み、結果を伝える。成功は `copied`（2 秒）、失敗はお知らせ帯と `manualText` |
| `components/records/CopyButton.tsx` | ボタン・「コピーしました」（`aria-live="polite"`）・失敗したときの文面の欄。要約・質問・字幕で使い回す |

### 文面の形

要約:

```
【全体の概要】
予算案を承認しました。

【話題ごとの要点】
・予算案: 承認された
・作業の分担: 来週決める

【決定事項】
・予算案を承認する

【宿題】
・該当なし
```

質問のまとまり 1 つ:

```
1. What is the budget plan?
   予算案は何ですか。

2. Who owns the task?
   誰が担当ですか。
```

字幕（時刻は PC のタイムゾーン）:

```
10:00:01 English line 1
日本語訳 1

10:00:02 English line 2
（訳なし）
```

- 要約: 4 項目の見出しを【】で囲む。全体の概要は文のまま、ほかの 3 つは 1 行 1 項目の「・」。内容が無い項目は「該当なし」。作成日時は含めない。
- 質問のまとまり: 「番号. 英語の質問」の次の行に、字下げした日本語の質問。まとまりの見出しと作成日時は含めない。
- 字幕: 「時刻 英語の原文」の次の行に日本語訳。日本語訳が無い字幕は「（訳なし）」。時刻は、字幕の行と同じ整形（`formatClockTime`。時:分:秒、PC のタイムゾーン）。
- 項目と項目の間は空行 1 行。末尾に改行を付けません。

Markdown の取り出し（PBI 6.4）は、`recordText.ts` の `SUMMARY_TITLES`・`NO_TRANSLATION_TEXT` と、`splitSummaryLines`・`formatDateTimeToMinute`・`formatClockTime` を使い回します。会議の内容の記号を、Markdown と HTML の記法として働かない形へ変換する処理は、取り出しの側に足します（コピーは、変換しない）。

### ボタンの出し分け

| ボタン | 置き場所 | 押せる条件 |
|---|---|---|
| 要約をコピーする | 要約の領域。要約を作るボタンの隣 | 要約がある（作り直しの途中や失敗のあとに表示している前の要約を含む） |
| 質問をコピーする | 質問のまとまりごと、質問の下 | 質問が 1 問以上ある |
| 字幕をコピーする | 字幕の領域の先頭 | 字幕が 1 件以上ある |

押せないときも、ボタンは押せない見た目で残します。「会議中」の画面の質問のコピーは、質問の領域がまだ無いため置いていません。質問を作る作業（PBI 5.5）で、`QuestionSetList` に `copyable` を渡すと、同じボタンを置けます。

### 結果の伝え方

| 結果 | 表示 |
|---|---|
| 成功 | 押したボタンの右に「✓ コピーしました」を 2 秒だけ出す。続けて押すと数え直す。お知らせ帯の失敗のお知らせは消す |
| ブラウザーが書き込みを断った（または `navigator.clipboard` が無い） | お知らせ帯にエラー `RECORD_COPY_FAILED`（コピーできなかったことと、欄の文面を選んで Ctrl+C を押す方法）。ボタンの下に、文面を全部選んだ読み取り専用の欄を出し、フォーカスを移す。欄を開いたまま、もう一度断られたときも、選び直してフォーカスを移す。欄の「閉じる」で閉じると、フォーカスはコピーのボタンへ戻り、お知らせ帯のエラーも消える |

- コピーできるのは、プレーンテキストだけです（`writeText`。HTML の形では書きません）。
- 会議の内容を、ログにもコンソールにも出しません。例外の文面は、画面にも出しません。
- `navigator.clipboard` は、安全な接続（https と `localhost`）のページにだけあります。アプリを `localhost` で開く使い方では使えます。コンテナ名などで開くと、`navigator.clipboard` が無く、上の失敗の表示になります。

## 記録の取り出し

「取り出す」で、記録を Markdown のファイル 1 つにして、ダウンロードさせます（F-13）。文面とファイル名は、読み込み済みの会議記録から画面が組み立てます（ADR-15）。アプリサーバーへ要求を送りません。Word 形式での出力はありません。

| 部品 | 役割 |
|---|---|
| `records/recordMarkdown.ts` | 記録から Markdown の文面を組み立てる純粋な関数（`buildRecordMarkdown`）。見出し・箇条書きの分け方・日時の整形・「該当なし」・「（訳なし）」は、コピーの文面（`recordText.ts`）と同じ部品を使う |
| `records/markdownEscape.ts` | 会議の内容の記号を、記法として働かない形へ変換する（`escapeMarkdownLine`・`escapeMarkdownParagraph`）。規則は次の節 |
| `records/exportFileName.ts` | ファイル名を決める（`buildExportFileName`） |
| `records/downloadTextFile.ts` | Blob と、`download` 属性を持つアンカーで、ダウンロードさせる。作った一時的な URL は、`REVOKE_DELAY_MS`（1 秒）のあとで解放する |
| `records/useRecordExport.ts` | 上の 3 つをつなぎ、失敗をお知らせ帯（`RECORD_EXPORT_FAILED`）で伝える |

### 文書の形

```
# タイトル

- 開始日時: 2026/11/05 10:00
- 会議の長さ: 1:30:15

## 要約

### 全体の概要

予算案を承認しました。

### 話題ごとの要点

- 予算案: 承認された

（決定事項・宿題も同じ。要約が無いときは「要約はまだありません。」の 1 文）

## 質問

### 質問のまとまり 2

- 作成日時: 2026/11/05 13:15
- 作成した時点: 会議後

1. What is the budget plan?  
   予算案は何ですか。

## 字幕

10:00:01 English line 1  
日本語訳 1
```

- 質問のまとまりは新しい順、字幕は話された順。会議の長さは、画面と同じ条件（通訳中でなく、終了日時がある）のときだけ書く。質問が無いときは「質問はまだありません。」、字幕が無いときは「字幕はありません。」。
- 質問と字幕の 2 行は、行末の 2 つの空白で改行する。日本語訳が無いときは「（訳なし）」。
- 全体の概要の段落の中の改行（次の行が空行でない行の終わり）も、行末の 2 つの空白で残す。画面は、概要の改行を見せる（`white-space: pre-line`）。Markdown の単独の改行は、空白として描画されるため、付けないと 1 つの段落につながる。空行は段落の区切りのまま。
- 要約作成中（要約を作り直している途中）と要約失敗の会議で、前の要約が残っているときは、要約の欄の初めに、前の要約であることを 1 行で書く（`前の要約です。要約を作り直している途中のため、前に作った要約を書いています。` と `前の要約です。要約の作成に失敗したため、前に作った要約を書いています。`）。画面の「前の要約」と同じ場合で、言葉も画面に合わせる（`recordText.ts` の `PREVIOUS_SUMMARY_LABEL`）。
- 日時は、画面の表示と同じ（PC のタイムゾーン）。文字コードは UTF-8（BOM なし）、改行は LF、末尾は改行 1 つ。種類は `text/markdown;charset=utf-8`。

### 記号の変換の規則

会議の内容（タイトル・字幕・要約・質問）は、すべて `markdownEscape.ts` を通して書きます。文書の骨組みに使う見出し・箇条書きの記号は、`recordMarkdown.ts` が書く固定の文字だけです。

| 対象 | 変換 | 止めるもの |
|---|---|---|
| `\` `` ` `` `*` `_` `{` `}` `[` `]` `\|` `#` `~` `$` | 前に `\` を付ける | 強調・コード・リンク・画像・表・取り消し線・属性・見出し・タグ・数式 |
| 2 つ続く `%%` と `==` | 続く記号のすべての前に `\` を付ける | コメント（`%%`）・強調（`==`）。1 つだけの `%` と `=` は、そのまま |
| `<` `>` `&` | `&lt;` `&gt;` `&amp;` | HTML の要素と文字参照。`\<` の形は、`\` を使えない変換器があるため使わない |
| 行頭の `-` `+` `=` `:` `!` | 前に `\` を付ける | 箇条書き・区切り線・見出しの下線・定義リスト・注記（`!!!`） |
| 行頭の「数字 ＋ `.` または `)`」（あとに空白か行末） | `.` または `)` の前に `\` を付ける | 番号つきの一覧（桁数の上限なし） |
| `//` | 1 つ目の `/` の直後に U+200B（長さ 0 の空白）を入れる | `scheme://`・`//host`・全角のコロンのあとの `//` など、`//` で始まる URL の自動リンク |
| `@` | 前後の両方に U+200B を入れる | メールアドレスの自動リンク。`@` の直後だけに入れる形は、linkify がホスト名の一部として読み、リンクになった |
| `www` のあとの `.` | 前に `\` を付ける | `www.` で始まる URL の自動リンク |
| 空白・`.`・`\` 以外の文字のあとで、あとに文字が 2 つ以上続く `.` | 前に `\` を付ける | 裸のドメイン（`example.com`）の自動リンク（linkify の fuzzyLink）。linkify がホスト名の文字を広く取るため（`x+.com`・`~.com`・U+200D のあとの `.com` もリンクになる）、前の文字を英数字に限らない。`3.5`・文末の `.`・`e.g.` には付かない |
| `1.2.3.4` の形の IP アドレスの中の `.` | 前に `\` を付ける | IP アドレスの自動リンク（linkify の fuzzyIP） |
| 文字の向きを変える文字（U+061C・U+200E・U+200F・U+202A〜U+202E・U+2066〜U+2069）と、見えないタグの文字（U+E0000〜U+E007F） | 取り除く | 表示の順序の偽装 |
| 行頭・行末の空白 | 取り除く | 字下げのコード、行末の 2 つの空白（改行） |
| 改行の別の形（U+2028 など）・制御文字 | 改行・空白にそろえる | 行頭の記法の抜け道。ターミナルでの制御 |

- 1 行の項目（タイトル・箇条書きの項目・質問・字幕）は、改行を空白 1 つに畳んで 1 行にします。複数行の内容（全体の概要）だけ、行を保ち、どの行の頭も変換します。
- `(` `)` と文の途中の `!` は変換しません。リンクと画像は `[` が要り、`[` を変換するためです。
- ZWJ（U+200D）と ZWNJ（U+200C）は残します。絵文字の結合と、一部の言語の文字の区切りに要るためです。ファイル名では、書式の文字（ZWJ・ZWNJ を含む）をすべて `_` にします（[ファイル名](#ファイル名)）。名前の見た目の偽装を避けることを、本文の表示より優先するためです。
- 変換した結果を、もう一度変換しません（`\` も変換するため、二重になります）。

URL の自動リンクの止め方（`//` と `@` は U+200B、ドットは `\`）を選んだ理由は、markdown-it で確かめた次の事実です。

- U+200B は、ドメインの文字として読まれます。`www\u200B.example.com` は、fuzzyLink でリンクになりました。そのため、ドットには使えません。
- `@` の直後だけに U+200B を入れた `user@\u200Bexample.com` は、リンクになりました（`mailto:user@xn--example-zz6c.com`）。前後の両方に入れると、ローカル部が `@` に隣り合わず、リンクになりません。
- `\` で逃がしたドット（`example\.com`）は、markdown-it 14.1.0 と 15.0.3 では、fuzzyLink でもリンクになりません（逃がした文字が、本文と別のトークン `text_special` になり、linkify が読む文字列に入らないため）。
- U+200B を入れると、表示される文字は元と同じですが、URL やメールアドレスをコピーすると、見えない文字が 1 つ入ります。

網羅できないもの（限界）:

- 変換器や、記録を開くアプリの設定で働く拡張記法は、すべては止められません。止めるのは、上の表の記号です。`:smile:` の絵文字の置き換え、GitHub の `#123`（`#` は止めます）・`@名前` の参照（`@` は止めます）のように、記号の組み合わせで決まった画像や参照に変わるものは、止めていません。要素やリンクの注入ではなく、変換器が持つ決まった置き換えのためです。
- markdown-it 14.1 より前の版は、`\` で逃がした文字を本文へ戻してから URL を探すと考えられます。その版では、`\` で止めた裸のドメインが、fuzzyLink でリンクになる可能性があります（未確認。確かめたのは 14.1.0 と 15.0.3）。
- Markdown の変換器の挙動は、版と設定で変わります。規則を変えたとき、または変換器を更新したときは、下の確認をやり直してください。

### 変換の確かめ方

`npm test` は、本物の Markdown の変換器（markdown-it。dev 依存。画面のコードからは import しない）で、取り出した文面を描画して確かめます（`test/records/recordMarkdownRendered.test.ts`）。設定は 2 つです。

- `{ html: true, linkify: true }`
- 上に、linkify の fuzzyLink・fuzzyEmail・fuzzyIP をすべて有効にしたもの（linkify-it の版で既定値が違うため、明示する）

確かめることは次のとおりです。

- 悪意のある内容（見出し・引用・一覧・区切り線・コード・強調・リンク・画像・HTML・文字参照・URL・メールアドレス・`//host`・全角のコロン・裸のドメイン・IP アドレス・`$x$`・`%%隠す%%`・`==強調==`・`!!!`・桁数の大きい番号・向きを変える文字など 109 例）を、1 行・段落として変換して描画すると、要素は段落だけで、表示される文字が元と同じ
- 記録の 9 つの項目（タイトル・要約の 4 項目・質問の英語と日本語・字幕の原文と訳）へ、悪意のある内容を 1 つずつ入れた文面を描画すると、出る要素は見出し・段落・一覧・改行だけ（`a`・`img`・`script`・引用・コード・表は出ない）で、骨組み（見出しと一覧の並び）が、無害な内容の文面と同じ。悪意のある内容は、表示される文字として残る
- メールアドレス・`//host`・全角のコロンの URL・`www.`・裸のドメイン・IP アドレスが、リンクにならない
- 生の HTML（`<script>`・`<img onerror>`・`<iframe>`・コメント）が通らない
- 決まった乱数で作った 2,000 通りで、要素は段落だけで、表示される文字が元と同じ
- 全体の概要の単独の改行が、改行の要素（`<br>`）として描画される

補助として、変換器を使わない規則による検査もあります（`test/records/markdownInertKit.ts` の先頭に説明があります）。変換した文字列から、有効な逃がし方を取り除いたあとに、記法として働くものが残らないこと、逃がし方を戻すと元の文字列になることを、109 例と、決まった乱数で作った 6,000 通りで確かめます。

出荷の前の確認として、別の版でも確かめました（コミットしていない使い捨てのスクリプト）。markdown-it 14.1.0（linkify-it 5.0.2）で、記録の 9 つの項目 × 109 例 = 981 通りの文面を、上の 2 つの設定で描画し、問題は 0 件でした（15.0.3 でも 0 件）。規則を変えたときは、同じ確認をやり直してください。

- 確かめていないもの: markdown-it 14.1.0 と 15.0.3 のほかの変換器（GitHub の自動リンクの拡張を持つ cmark-gfm、Obsidian、Typora など）。`//`・`@` を U+200B で割る規則と、ドットの `\` は、それぞれの変換器の自動リンクの読み方に合うと考えられますが、実行していません。

### ファイル名

`開始日時_タイトル.md`（例: `20261019-1430_週次の定例.md`）。

- 開始日時は、PC のタイムゾーンで「年月日-時分」。画面の開始日時（`formatDateTimeToMinute`）の整形から数字だけを取り出して作るため、画面と同じ時刻になる。0 時は `0000`（`2400` にならない）。
- タイトルのうち、ファイル名に使えない文字（`\ / : * ? " < > |`）、制御文字、見えない文字（U+200B・U+202E など）は `_` に置き換える。改行・タブ・続く空白は、空白 1 つに畳む。
- 長いタイトルは 50 文字（コードポイントの数）で切る。4 バイトの文字だけでも、名前全体が UTF-8 で 255 バイト以内に収まる。末尾の「.」と空白は取り除く。
- 意味のある文字が残らないとき（空・空白だけ・`_` と「.」だけ）は、開始日時だけ（`20261019-1430.md`）。
- Windows の予約名（`CON` など）にはなりません。名前が必ず開始日時の数字から始まるためです。

### ボタンと案内

| 部品 | 置き場所 | 押せる条件 |
|---|---|---|
| 取り出す | 見出しの領域。「一覧へ戻る」と「記録を削除する」の間 | どの状態でも押せる（通訳中・中断・要約作成中・完了・要約失敗。字幕や要約が無くても） |

- Tab の順は、「一覧へ戻る」→「取り出す」→「記録を削除する」。Enter でも Space でも押せる。押したあとも、フォーカスは「取り出す」に残る。
- 案内は、画面の最後に常に表示する（「記録の残し方」。残したい記録はテキストファイルで取り出すこと、取り出す方法、バックアップ機能が無いこと）。
- ブラウザーがダウンロードを始められなかった（Blob の URL を作れないなど）ときは、お知らせ帯にエラー `RECORD_EXPORT_FAILED`。次に取り出せると消える。例外の文面は、画面にもログにも出さない（[errors.md](errors.md)）。
- ダウンロードの CSP: 配信部の `default-src 'none'` のもとでも、`blob:` の URL のダウンロードは止まらない（出荷のコンテナの Chrome で確かめた。コンソールのエラーは 0 件）。
