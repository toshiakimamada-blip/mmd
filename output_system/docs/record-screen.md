# 「会議の記録」の画面

「会議の記録」の画面（S-04）の作りと、動作の確認です。設計の根拠は、基本設計書の画面設計書「S-04 会議の記録の領域」「S-04 会議の記録の項目と操作」「状態別の表示と操作」「複数の画面で使う項目」、機能設計書 F-10・F-15、ADR-15 にあります。

暫定版（2026-11-16 まで）では、質問を作るボタン、記録の削除、書き出し、コピーを置きません。質問は、まとまりがあれば表示し、なければ「質問はまだありません。」と表示するところまでです。

## 画面の作り

| 領域 | 中身 | 部品 |
|---|---|---|
| 見出しの領域 | タイトル、開始日時、会議の長さ（通訳中は出さない）、状態、「一覧へ戻る」 | `screens/record/RecordHeader.tsx` |
| 要約の領域 | 状態に応じた内容（会議中・中断・内容なし・作成中・要約・失敗）と、「要約を作る」「要約を作り直す」のボタン | `screens/record/SummaryRegion.tsx`、`SummaryContent.tsx`、`SummaryProgress.tsx` |
| 質問の領域 | 質問の作成状況（待機中・作成中）、質問のまとまり（新しい順。作成日時・作成した時点・質問 5 問を英語と日本語で並べる） | `screens/record/QuestionRegion.tsx`、`components/questions/QuestionSetList.tsx` |
| 字幕の領域 | 話された順の字幕（「会議中」と同じ `SubtitleRow`） | `screens/record/SubtitleRegion.tsx` |

要約の 4 項目は、保存した文字列を 1 行ずつ箇条書きにして、文字として表示します（`records/summaryLines.ts`）。HTML や Markdown としては解釈しません。

## 状態別の表示と操作

会議の状態・字幕の件数・要約の有無・作成ジョブから、要約の領域の内容とボタンを決める表は、`records/recordView.ts` の 1 か所にあります（純粋な関数）。表のすべての行を `test/records/recordView.test.ts` が確かめます。質問を作るボタンと削除の可否も同じ関数が答えますが、暫定版は画面に置きません。ボタンを足すときに、出し分けを作り直さないためです。

## 記録の読み込みと通知での更新

`GET /api/meetings/{会議番号}` で、会議・字幕・要約・質問のまとまり・作成ジョブを 1 回で読みます（`records/useMeetingRecord.ts`）。

| きっかけ | 動き |
|---|---|
| 会議が無い | 「会議の一覧」へ移り（履歴は置き換え）、お知らせ帯に記録が見つからないことを出す |
| 読み込みの失敗 | お知らせ帯にエラーを出す。次に読み込めると消す |
| `meeting.state_changed`・`job.status_changed` | 記録を読み直す |
| `job.progress_changed` | 作成ジョブの処理したブロックの数だけを差し替える（ブロックごとに届くため、読み直さない） |
| 通知の接続がつながった（つなぎ直しを含む） | 記録を読み直す |
| ほかの会議の通知 | 読み捨てる |

要約の失敗は、会議に保存したエラーコードから表示します。画面を開き直しても同じ表示になります。

## 動作の確認（出荷するコンテナ）

`docker compose build` で作り直したイメージのコンテナ（開発用コンテナからコンテナ名で接続）を、`playwright-cli`（Chrome、画面幅 1280）で開いて確かめました。会議は、`POST /api/meetings` で始め、`/ws/audio/{会議番号}` へ、英語の演説（faster-whisper の `tests/data/jfk.flac`。前に 1 秒、後ろに 2 秒の無音を足した）を実際の速さで送り、`POST /api/meetings/{会議番号}/end` で終えました（本物のモデル。タイトルは `<b>週次</b> & 定例`）。

| 確かめたこと | 結果 | スクリーンショット |
|---|---|---|
| 通訳中の会議を開くと、それまでの字幕が出て、要約の欄に会議中であることが出る | 合格 | `task-108_record-while-interpreting.png` |
| 終了の直後、状態が要約作成中になり、要約の欄に作成状況（待機中と、待機中の添え書き）が出る | 合格 | `task-108_record-summary-starting.png` |
| 要約の作成中は、作成状況（作成中）と、処理したブロックの数が出る | 合格 | `task-108_record-summary-running.png` |
| 完了すると、4 項目・箇条書き・「該当なし」・作成日時・「要約を作り直す」が出る。タイトルの HTML は文字のまま | 合格 | `task-108_record-summary-done.png` |
| 「要約を作り直す」を押すと、作成状況（待機中）と、待機中の添え書き、前の要約が出る | 合格 | `task-108_record-summary-rebuilding.png` |
| 開いたまま（読み直しなし）で作成が終わると、新しい要約（作成日時が進む）に変わり、状態が完了になる | 合格 | `task-108_record-summary-rebuilt-by-notification.png` |

最後の確認は字幕 3 件の会議で、要約の作成に約 2 分でした（この開発環境）。それ以前の確認は、約 80 秒の会議（字幕 17 件）です。

実ブラウザーでは確かめていません（Vitest で確かめました）: 要約の失敗の表示、質問のまとまりの表示（暫定版では質問を作れないため）、画面幅 390、2 時間・約 1,500 件の字幕の描画（Vitest は 1,500 件の表示を確かめます）。
