# 通訳ワーカー

通訳ワーカーは、会議の間だけ動く別のプロセスです。16kHz・モノラルの音声を受け取り、無音で発話を区切り、英語の文字にして日本語へ訳し、字幕を返します。画面や会議管理部が無くても、音声ファイルを流して動かせます。

設計の根拠は、基本設計書の `functional.md`（F-04、F-05）、`architecture.md`（通訳ワーカー）、`adr.md`（ADR-04、ADR-05、ADR-07）と `nonfunctional.md`（字幕の遅れの配分、メモリの配分）にあります。

## 構成

コードは `backend/src/meeting_interpreter/interpreter/` にあります。

| ファイル | 役割 |
|---|---|
| `protocol.py` | 親と子の間のメッセージの型と、パイプに流す形（長さつきのフレーム）。音声は 1 秒 32KB のため、共有メモリは使わずパイプで送る |
| `client.py` | 親（アプリサーバー）側。ワーカーの起動・音声の送信・受信・停止。起動は `child_process.py` の入口だけを使う |
| `entry.py` / `__main__.py` | ワーカーのプロセスの入口。外へ通信しない備えを入れてから、AI の部品を取り込む |
| `worker.py` | 本体。音声を区切り、待ち行列へ入れ、できた順に字幕にする |
| `segmenter.py` / `vad.py` | 発話の区切り。声の検出は Silero VAD（faster-whisper に同梱の ONNX 形式を ONNX Runtime で動かす。PyTorch は使わない） |
| `transcriber.py` | 文字起こし（faster-whisper で Whisper small.en。8 ビットに量子化、CPU のみ） |
| `translator.py` | 翻訳（CTranslate2 で変換済みの FuguMT）。差し替え口 `engines.Translator` の裏に置く |
| `engines.py` / `fake.py` | 本物のエンジンの組み立てと、自動テスト用の偽のエンジン |
| `locations.py` | モデル置き場の中の、2 つのモデルの場所 |

受け取りと処理は別のスレッドです。処理が音声に追いつかなくても、音声を受け取り続け、捨てません。処理を待つ音声の長さを、遅れの見込みとして 1 秒ごとに親へ知らせます。

## 調べ方

### 自動テスト

通常の `uv run pytest` は、偽のエンジンで動かします。本物の AI モデルで動かすテスト（`test_interpreter_real_models.py`）は、環境変数を指定したときだけ動きます。

| 環境変数 | 中身 |
|---|---|
| `MMD_TEST_MODELS_DIR` | モデル置き場（`<置き場>/<モデル名>/<版>/` の配置）。コンテナの `/var/lib/mmd/models` から、`whisper-small-en` と `fugumt-en-ja` を `docker cp` で取り出して作る |
| `MMD_TEST_SPEECH_FILE` | 英語の音声ファイル（10 秒ほどのはっきりした英語の発話） |

### 字幕の遅れとメモリの測定

`backend/` で、次を実行します（`uv run` の代わりに `.venv/bin/python` でもよい）。結果は標準出力に出ます。

```bash
uv run python test/measure/measure_interpreter.py \
    --models-dir /tmp/mmd-models --speech /tmp/jfk.flac --repeat 6
```

| 引数 | 意味 |
|---|---|
| `--repeat` | 音声を繰り返す回数 |
| `--gap` | 音声の間の無音（秒、既定 1.5）。0 にすると、つなげた音声が上限（5 秒）で区切られる場面を作れる |
| `--speed` | 送る速さ（既定 1 = 実際の速さ）。3 にすると、処理が追いつかない場面を作れる |
| `--utterance-max` `--end-silence` `--transcription-beam` `--translation-beam` `--threads` | 調整値を、実行の間だけ変える |

出力は、字幕ごとの段別の時間の表、遅れの平均と最大、処理を待つ音声の最大、ワーカーの常駐メモリ、PC の使えるメモリ（`MemAvailable`）の変化、ワーカーが数えた「外へ通信しようとした回数」です。

## 測定結果（2026-10-28）

開発環境で、本物のモデルを使って測りました。基本設計書の定めでは、開発環境の値は参考値で、目標の判定には使いません（`nonfunctional.md`「実際に使う状態での測定」）。実際に使う状態の測定は、同時通訳・要約・質問が動くようになってから行います。

### 測った条件

| 項目 | 内容 |
|---|---|
| PC | Intel Core i7-1185G7（8 スレッド）、メモリ 約 7.6GB。開発用のコンテナの中で測定した。アプリのコンテナ（待機中）も動いていた。テスト用のブラウザーと会議アプリは動かしていない |
| モデル | Whisper small.en（8 ビット）、FuguMT（CTranslate2、8 ビット）、Silero VAD。入手済みのモデルを使った |
| 調整値 | `config/tuning.toml` の同梱の値のまま。CPU スレッド 6、区切りの上限 5.0 秒、区切りを確定する無音 0.5 秒、ビーム幅は文字起こしも翻訳も 1 |
| 音声 | 英語の演説の 11.0 秒の音声（faster-whisper の `tests/data/jfk.flac`、SHA-256 `63a4b1e4…949715`）を、前後の無音つきで 6 回流した（1 回 76 秒）。リポジトリには入れていない。使用の権利は確認していないため、参考値の測定にだけ使った |
| 送り方 | 0.5 秒ずつ、実際の速さで送った。字幕の遅れは、区切りの先頭の音声を送った時刻から、字幕を受け取った時刻まで |

測定は 5 回行いました。実際の速さの 4 回（回 1・2・4・5、96 件）が、遅れの値の元です。回 3 は、処理が追いつかない場面を作るため 3 倍の速さで送りました。

| 回 | 内容 | 件数 |
|---|---|---|
| 1 | 実際の速さ。音声の間の無音 1.5 秒 | 24 |
| 2 | 実際の速さ。音声の間の無音 0 秒（つなげた音声が、上限 5 秒で区切られる場面を含む） | 24 |
| 3 | 3 倍の速さ（処理が追いつかない場面） | 24 |
| 4 | 実際の速さ。測定の間、ワーカーのソケットを 0.5 秒ごとに調べた | 24 |
| 5 | 実際の速さ。ネットワークの無い名前空間（`unshare -n`）の中で実行 | 24 |

### 字幕の遅れ（配分との比較）

| 段 | 配分（仮置き） | 測った値（実際の速さの 4 回、96 件） | 配分に収まったか |
|---|---|---|---|
| 発話の区切りができるまで | 最長 5 秒 | 発話の長さ 0.5〜3.2 秒に、区切りを確定する無音 0.5 秒を足した時間。上限で区切った 5.0 秒の発話が 1 件 | 収まった |
| 処理の待ち | （配分に無い） | 最大 2.44 秒 | — |
| 文字起こし | 3 秒以内 | 平均 2.1〜2.5 秒、最大 3.70 秒。**3 秒を超えたのは 7 件（7%）** | 超えた件がある |
| 翻訳 | 1 秒以内 | 平均 0.16〜0.20 秒、最大 0.49 秒 | 収まった |
| 保存と通知 | 0.5 秒以内 | 測っていない（アプリサーバー側。この PBI の範囲外） | 未測定 |
| 余裕 | 0.5 秒 | — | — |
| **合計（先頭の音声が届いてから字幕まで）** | **10 秒以内** | **平均 5.3 秒、最大 7.6 秒**（保存と通知を除く） | 収まった |

回ごとの値は次のとおりです。

| 回 | 遅れ（平均／最大） | 文字起こし（平均／最大） | 翻訳（平均／最大） | 処理を待つ音声の最大 |
|---|---|---|---|---|
| 1 実際の速さ | 5.5 秒／7.1 秒 | 2.52 秒／3.62 秒 | 0.18 秒／0.31 秒 | 2.7 秒 |
| 2 つなげた音声 | 5.0 秒／7.6 秒 | 2.10 秒／2.84 秒 | 0.16 秒／0.22 秒 | 2.5 秒 |
| 3 3 倍の速さ | 16.7 秒／30.8 秒 | 2.08 秒／2.94 秒 | 0.15 秒／0.20 秒 | 29.8 秒 |
| 4 ソケットの調査つき | 5.6 秒／6.5 秒 | 2.49 秒／3.18 秒 | 0.20 秒／0.49 秒 | 2.7 秒 |
| 5 ネットワーク無し | 5.0 秒／7.0 秒 | 2.26 秒／3.70 秒 | 0.17 秒／0.25 秒 | 1.3 秒 |

分かったことです。

- 実際の速さでは、遅れは最大 7.6 秒で、目標の 10 秒以内でした。ただし、保存と通知（配分 0.5 秒）は含みません。話者 1 人のはっきりした演説で、実際の会議の音声では測っていません。
- 文字起こしは、区切りの長さにほとんど依りません。1.5 秒未満の区切りは平均 2.11 秒、1.5〜3 秒は 2.44 秒、3〜4.9 秒は 2.26 秒、5 秒は 2.35 秒でした（原因は調べていません）。
- 上の結果から、短い発話が約 2 秒より短い間隔で続くと、処理が追いつかず、処理を待つ音声がたまると考えられます（推測。短い発話が続く音声では測っていません）。たまった場合の動きは、3 倍の速さの回で確かめました。24 件すべてが話された順に出て、音声は捨てられませんでした。待つ音声は最大 29.8 秒、遅れは最大 30.8 秒になりました。
- 文字起こしの配分（3 秒）を超えた 7 件は、合計の遅れが 10 秒以内に収まりました。区切りの長さが配分より短い場合は、余りがあるためです。配分の見直しは、実際に使う状態の測定を見て決めます。
- 調整値は変えていません。実際に使う状態の測定で、見直しが要るか確かめます。

### メモリ（配分との比較）

| 項目 | 配分（仮置きの上限） | 測った値 |
|---|---|---|
| 通訳ワーカー（利用時） | 2.0GB | 準備完了 574〜613MB、実行中の最大 795〜824MB（常駐メモリの最大値。5 回） |
| 通訳ワーカー（自動テスト時） | 1.5GB | 同上。配分の約 55% |
| PC の使えるメモリ（起動の直後） | — | 起動前から 463〜616MB 減った |
| 停止後 | 「AI モデルのメモリが戻る」 | 停止後の使えるメモリは、実行中より 612〜697MB 多く、起動前との差は −216〜+70MB（ファイルのキャッシュの増減の範囲）。ワーカーのプロセスは残らなかった |

- 測ったのは通訳ワーカーだけです。アプリサーバーと、開発用のコンテナ、テスト用のブラウザーを足した、場面ごとの合計は測っていません。
- ワーカーの起動から準備完了までは 1.6〜3.4 秒でした（うち、モデルの読み込みは 1.4〜3.3 秒）。ファイルのキャッシュが効いた状態の値で、初回の読み込みは測っていません。会議開始時の待ち時間の目標（2 分以内）に対する測定は、会議管理部ができてから行います。
- 区切りの音声は、字幕を出した時点で参照を外します。実行中の最大値に、長い会議で増え続ける傾向があるかは、2 時間の連続の測定で確かめます（この PBI では 76 秒だけ測りました）。

## 外へ通信しないことの確認

通訳ワーカーは、3 段の備えで外へ通信しません（基本設計書 ADR-14。仕組みは翻訳モデルの変換と共通で、[docs/models.md](models.md)の「変換のために外へ通信しない」にあります）。

1. 環境変数: 自動入手と利用状況の送信を止める。起動は `child_process.py` の入口だけで、呼び出し側から外せない
2. Python の見張り（`network_guard.py`）: ソケットの作成・接続・名前の解決を拒んで数える。停止完了のメッセージの `network_attempts` で親へ知らせる
3. OS の仕組み（`sandbox.py`）: seccomp で、UNIX ドメイン以外のソケットを作れなくする。入れられないときは、AI の部品を動かさず、開始を失敗にする

本物のモデルで確かめた結果です。

| 確かめた内容 | 結果 |
|---|---|
| 停止完了の `network_attempts` | 本物のモデルで、測定 3 回（回 4・回 5 と、動作の確認の短い測定）と `test_interpreter_real_models.py` が、毎回 0。回 1〜3 は、この値を出力する前の測定で、確認していない |
| 動いているワーカーの OS の仕組み | `/proc/<PID>/status` が `Seccomp: 2`、`Seccomp_filters: 1` |
| 動いているワーカーのソケット | 測定の間に 140 回（0.5 秒ごと）調べ、ソケットのファイル記述子は 0 個、TCP・UDP・RAW のソケットも 0 個（`ss -p`）。短い接続は取りこぼしうるため、この調査だけでは根拠にしない。上の 2 つが根拠 |
| ネットワークが無い環境 | `unshare -n`（ループバックも停止）の中でも、同じ音声から 24 件の字幕が出た |

## 引き継ぎ

- 親（アプリサーバー）が字幕の順番を振る。ワーカーは順番を持たず、話された順に出力するだけ
- 日本語の発言が混じっても判別せず、そのまま処理する。意味の通らない字幕が出ることがある（画面で案内する）
- 無音や雑音から Whisper が出す幻覚（「you」など）は、声が無い確からしさが 0.6 を超える区間を除いて防ぐ（`transcriber.py`）
- 前の区切りの文章を、次の区切りの条件に使わない
